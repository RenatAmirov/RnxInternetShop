# Тихий дом

Интернет-магазин товаров для дома. Витрина, корзина, оформление и история заказов реализованы страницами ASP.NET Core Blazor Web App с серверным рендерингом. Корзина и история доступны владельцу сессии в том же браузере.

## Запуск

Требуется Docker с Compose. Запустите проект из корневой папки.

```sh
docker compose up --build -d
```

- [Витрина](http://localhost:5088/)
- [Mailpit](http://localhost:18025/) показывает письма покупателям и менеджеру в локальной среде.
- [RabbitMQ Management](http://localhost:25673/) показывает очереди и сообщения. Локальный логин `shop`, пароль `shop-local`.

Приложение создаёт таблицы PostgreSQL и добавляет шесть товаров при первом запуске. Остановка контейнеров через `docker compose down` сохраняет заказы, очереди, почту и ключи сессий в Docker-томах.

Для работы над кодом с локальным .NET 10 SDK запустите зависимости и само приложение.

```sh
docker compose up -d --wait postgres redis rabbitmq mailpit
dotnet run --launch-profile Shop
```

## Оформление заказа

1. PostgreSQL сохраняет заказ, цены товаров и событие в таблице `outbox` одной транзакцией. Повторная отправка формы с той же версией корзины возвращает уже сохранённый заказ.
2. Фоновый процесс публикует событие в RabbitMQ и помечает его опубликованным после подтверждения брокера. Если RabbitMQ временно недоступен, событие остаётся в PostgreSQL.
3. Отдельные очереди запускают письмо покупателю, письмо менеджеру, уведомление в карточке заказа, запись в журнале и SMS при согласии покупателя. Ошибка одного обработчика допускает повтор из его очереди с задержкой. После исчерпания попыток сообщение поступает в соответствующую очередь `.dead`.
4. Таблица `processed_effects` защищает внутренние записи от повторной обработки. У каждого e-mail стабильный `Message-ID`, а SMS-запрос содержит `Idempotency-Key`. При разрыве между приёмом письма SMTP-сервером и фиксацией результата в БД SMTP может доставить дубликат.

Redis кэширует каталог на пять минут. При сбое Redis каталог читается из PostgreSQL. Для расчёта суммы при оформлении используются цены из PostgreSQL.

## Доставка писем и SMS

В локальном Compose оба письма принимает Mailpit, а SMS сохраняются в демонстрационном журнале PostgreSQL. Команда ниже выводит записи этого журнала.

```sh
docker compose exec -T postgres psql -U shop -d shop -c "select recipient, message, created_at from demo_sms_inbox order by created_at desc"
```

Для подключения SMTP задайте переменные окружения приложения `Mail__Host`, `Mail__Port`, `Mail__Security` (`StartTls` или `SslOnConnect`), `Mail__From`, `Mail__Manager` и при необходимости `Mail__Username` и `Mail__Password`.

Для подключения SMS задайте `Sms__Webhook` с URL провайдера или адаптера, `Sms__DemoInbox=false` и при необходимости `Sms__ApiToken`. Приложение отправляет POST с JSON вида `{"to":"+79991234567","text":"Тихий дом: заказ №1001 принят."}`, заголовком `Idempotency-Key` и, при наличии токена, `Authorization: Bearer …`. Успешный ответ имеет статус 2xx. Чтобы исключить повторную доставку, адаптер должен учитывать ключ идемпотентности.

Для передачи этих переменных контейнеру `shop` их можно задать в локальном `compose.override.yaml`.
